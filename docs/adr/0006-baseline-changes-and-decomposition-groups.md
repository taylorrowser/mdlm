# Baseline changes and decomposition groups

Tiny 0.5.0 stores decomposition in exact DCP groups selected by RQS, replacing
parent edges embedded in REQ for fresh repositories. A changed parent can then
receive a fresh decomposition assessment while unchanged children and their
deeper groups retain their exact revisions. Historical packages and selections
keep their original representation.

Each review assesses individual children against their parent and the group's
collective adequacy. Neither judgment implies the other. The CLI refreshes group
endpoint links and derives required assessments; agents decide semantic validity.
This avoids revising an entire descendant tree merely to repair exact references.

Accepted ACC evidence establishes the baseline without another baseline datum or
freeze stage. Subsequent controlled changes require an approved CHG, with one
active change per accepted product lineage. Existing package obligations and
`next` derive work rather than a separate queue database. Unchanged children stop
downward propagation; changed children continue it. Every affected parent context
of a shared child remains a separate review obligation.

RQS retirement links explicitly remove requirements from successor selections.
They preserve history and distinguish retirement from removing one shared-child
membership. Approval authorizes scope, review judges adequacy, and a new accepted
ACC closes the change. A clarification can complete without child or code edits.
