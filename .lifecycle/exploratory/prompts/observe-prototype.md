# Observe and recommend

Run this exact Assignment with `mdlm assignment run --json`. Inspect its captured output before submitting an assessment. The CLI supplies outcome and receipt; never author them. Distinguish scripted evidence, agent-observed interaction and actual user observations. Use scripted origin and explicitly say human use has not been observed when that is all the evidence. Record limitations. Recommend keep, revise, drop or nominate. A nomination proposes one supported behavior for later requirements work; it does not accept the product or baseline anything. In next_action state the nomination wording or the change to try. Failed or errored execution permits revise or drop, not keep/nominate. A passing script alone cannot establish user comfort. A revise recommendation produces a new brief revision; the previous evidence stays exact.

Nomination requests attended stakeholder feedback through the next Assignment. Do not treat it as a terminal decision or supply stakeholder authority yourself. Keep and drop remain bounded agent recommendations that end this experiment without acceptance.
