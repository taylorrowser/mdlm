# Revise the experiment

Use this action when the intent, criterion, constraints or provisional approach
needs to change. If a revise observation identifies only a product defect under
unchanged exact intent and interfaces, use `correct-prototype` on the current
EXP. If the verifier is faulty, revise it independently and use
`update-criterion-verification-selection`. A changed EXP needs independently
authored verification bound to its exact new context, even when some wording
stays the same.

Read the exact prior brief and triggering observation or stakeholder feedback. Preserve useful intent and change only what the evidence warrants. Explain the revision in the body. Link to the exact trigger. Keep prior observations as historical evidence, not proof of the new prototype. A brief revision may retain its criterion while changing a provisional approach; do not imply that unchanged criteria were changed. Criteria and choices remain provisional. Set a sensible new allowance and scope cut. This is a new revision of the same brief, not a stakeholder commitment.

Read `subject`, `observation` and optional `baseline` from guidance. Keep the generated exact `responds-to` and `compares-to` links, including the unchanged accepted comparison across criteria revisions. A candidate may intentionally depart from named requirements; record the departure and discovered effects in constraints or the body. This does not revise the accepted promise.

Select the complete necessary public ICD set with exact `uses-interface` links
on the revised EXP. Retain unchanged interfaces and adopt changed ones
explicitly before exporting the new criterion context. If the current EXP has
no TRY yet, optional `amend-experiment` supports this without an observation.
