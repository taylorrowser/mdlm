# Write a pilot verification activity

Read, in order:

1. `skills/lifecycle-data.md@1`
2. `skills/verification-writing.md@1`
3. `skills/verification-independence.md@1`

Write from the exact requirement and strategy, not product source, unit tests, or
private implementation notes. Define one activity expected to succeed for a
declared supported behavior and one expected to expose intentionally unsupported
or incorrect behavior. The activity evaluates whether the verification design is
executable and discriminating; it does not accept the requirement.

Before proposing authored Lifecycle Data, apply the bounded ephemeral
`skills/author-preflight.md@1` contract.
