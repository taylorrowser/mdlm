# Requirement writing

Each requirement must be:

- **singular:** one independently assessable commitment;
- **necessary:** removing it would break a traced parent or accepted decision;
- **unambiguous:** actor, behavior, conditions, and outcome are clear;
- **level-appropriate:** STK is stakeholder-visible; SYS is system-level and
  solution-independent;
- **verifiable:** its fit criterion or verification intent describes observable
  evidence without prescribing a test implementation;
- **rationale-backed:** rationale explains why, not a restatement of what;
- **traceable:** every derivation uses allowed links to authorized intent.

Avoid conjunctions hiding multiple obligations, vague adjectives, passive actors,
architecture disguised as behavior, and requirements created only for convenience.
