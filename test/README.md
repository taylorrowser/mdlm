# Current direct lifecycle checks

`npm run test:fast` checks types, builds the CLI and runs focused retained checks.
`npm run test:cutover` also runs both public lifecycle journeys, all Pi tests,
and repeats the journeys through an npm installation of the exact source tree.
`MDLM_DIRECT_EXECUTABLE` pins an existing installed executable for the journeys.
Public evidence is preserved outside each lifecycle repository on success and failure.

The supported inventory is in `vitest.suites.mjs`. All surviving TypeScript tests
remain included in the root typecheck. Removed Assignment, Scenario, scheduling,
lease and historical full-process fixture tests are available in Git history;
previous release evidence remains in its original operational records.

Coverage retained across the cutover:

- Source scopes validate complete committed-line attribution, exact selected leaf
  targets, many-to-many regions and truthful blank/documentation exemptions.
- Requirement graph v2 and change assessments retain exact historical graphs,
  decomposition adequacy, explicit retirement and approved correction frontiers.
- Direct domain checks derive membership atomically and update group endpoints
  while retaining unchanged children. Authored generated data is rejected.
- Direct receipt checks prevent uncertain execution replay, recover completed
  receipts unchanged and reject mismatched exact execution bindings.
- Direct authority checks bind independently registered verdict and proposal bytes
  to exact context; stakeholder authority cannot be supplied by reviewer evidence.
- Public journeys exercise current tiny and exploratory packages through direct
  commands, real execution, decisions and corrections. They use explicit fixture
  stakeholder delegation and do not claim real user acceptance.
- Package loading and runtime scans reject restoration of old workflow machinery.
- CLI output flush, schema diagnostics, expression predicates and release identity
  guards preserve the independent boundaries they protected before the cutover.

Pure receipt and authority tests construct only the isolated storage/context needed
for rejection checks. Public journeys start empty and author every lifecycle datum
through supported operations.
