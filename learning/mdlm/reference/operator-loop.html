Quick reference

The operator loop

MDLM derives work from repository truth. It does not advance a hidden workflow cursor.

1. Evaluate
mdlm status --json classifies repository truth. mdlm next --json returns one Operator Outcome and allocates an Assignment only when work can advance.
↓
2. Prepare
mdlm scenario prepare <assignment-id> --json binds the exact package, repository state, Scenario, prompt, skills, inputs, participation, outputs, and completion conditions.
↓
3. Perform
The harness or attended authority does the declared work. MDLM itself does not perform agent work.
↓
4. Submit
mdlm scenario submit validates a complete Assignment Response. A valid proposal publishes one atomic Scenario transaction as Lifecycle Data.
↓
5. Verify and commit
mdlm doctor --json, inspect the exact diff, then commit it with ordinary Git.
↓
6. Reevaluate
Run status and next again. New Lifecycle Data may satisfy old Obligations, create new ones, expose attention, reach a boundary, or reveal a defect.

Do not collapse these terms

Obligation Instance
One evaluated requirement for one exact subject and process reference.
Loose End
An unsatisfied Obligation reported with blockers, dispatchability, resolver, outputs, and waiver policy.
Scenario
A versioned contract for bounded agent work.
Assignment
An exact state-bound projection of one Scenario transaction for one agent. It is not Lifecycle Data.
Operator Outcome
The result of reevaluation. It may be Assignment, Attention Required, a successful boundary, Process Dead End, or Invalid.
