Quick reference

What MDLM stores and computes

Stored package declarations

These versioned files define how MDLM should interpret repository facts.

  • Phases
  • Obligations
  • Scenarios and prompts
  • Selectors, Policies, and Computed State definitions
  • Lifecycle Data type definitions

Stored Lifecycle Data

These Markdown records are authoritative product claims, evidence, and history.

  • Stable Data and immutable Revisions
  • Links and creation provenance
  • Validated Scenario transaction outputs

Derived on evaluation

MDLM computes these from the selected package and current Lifecycle Data. They are not mutable tracking files.

  • Active Phase
  • Obligation Instances
  • Loose Ends and blocker chains
  • Dispatchability
  • Computed States
  • Operator Outcome

Temporary operator state

.lifecycle/work/active-assignment.json records the current Assignment lease. The lease prevents a later command from silently allocating conflicting work against a different repository state. Git ignores this file. It is not Lifecycle Data.

Phase progression is separate. A Phase lists applicable Obligations and also declares its own readiness and authorization expressions. Do not infer progression merely because an Obligation list looks complete.
