Who chooses the next work?

Replace the idea of a scenario sequence with a more exact model: repository truth is reevaluated, and the resulting obligations expose work.

Your tangible win. By the end, you should be able to explain why a successful Scenario does not tell MDLM what to run afterward.

Start with the correction

Your model was close: the agent repeatedly asks MDLM what to do, performs bounded work, and returns the result. The missing piece is what causes that work to appear.

A Scenario is a reusable contract. It does not schedule itself. The Process Package declares Obligations and other conditions. The kernel evaluates those declarations against exact Lifecycle Data. That evaluation produces an Operator Outcome. When work is safe to dispatch, the outcome contains an Assignment bound to one Scenario and exact inputs.

Repository truth
Lifecycle Data, exact Revisions, links, package provenance, and transaction evidence.
↓ evaluated with
Process Package
Selectors, Policies, Computed States, Obligations, Scenarios, Phases, and profile conditions.
↓ produces
Operator Outcome
Perhaps an Assignment. Perhaps attention, a successful boundary, a dead end, or an invalid result.

The Assignment is temporary orchestration context. It freezes the exact state needed for one proposed transaction. If the proposal passes submission checks, MDLM publishes its outputs as Lifecycle Data. Then the operator reevaluates. The new data may satisfy an Obligation or cause different Obligations to exist.

A small example

Suppose the package requires a Product Specification. No valid PSP exists.

  1. The applicable Obligation Instance is unsatisfied.
  2. Its Loose End identifies a Resolver Scenario and exact bindings.
  3. If blockers are clear, mdlm next may allocate an Assignment for that Scenario.
  4. The agent proposes a PSP through the Assignment Response.
  5. Submission validates and atomically publishes the PSP.
  6. Reevaluation checks the obligation again. It does not trust the agent's claim that the work is done.

This is why MDLM has no hidden “advance to the next step” operation. New truth changes evaluation.
