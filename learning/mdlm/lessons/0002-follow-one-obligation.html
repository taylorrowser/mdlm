Lesson 2 · 10 to 15 minutes

Follow one Obligation

Trace the first Phase 0 requirement from a package rule to one exact Assignment.

Goal. Given an Obligation definition, explain why MDLM reports work and which Scenario may resolve it.

A Phase is a package-declared scope that enables a set of rules and work contracts. A Subject is the specific Phase or piece of Lifecycle Data to which a rule applies. This lesson uses the first Phase, named Phase 0.

The six forms of work

Read these once. Keep the glossary open if the names blur together.

  1. An Obligation is a package rule stating what must be true.
  2. An Obligation Instance applies that rule to one exact subject.
  3. A Loose End is an unsatisfied instance that MDLM reports.
  4. A Resolver Scenario is the declared work contract that may produce the missing evidence.
  5. Dispatchable means the inputs resolve and declared blockers are clear.
  6. An Assignment is a temporary work packet that binds the Scenario to the current repository state for one response.

A real package rule

Phase 0 begins by requiring one wayfinding map. The live definition is initial-wayfinding-map-required@2.

for_each: '[phase]'
subject_as: required_phase
satisfied_when: 'exists("current-wayfinding-maps@1", {})'

status_rules:
  - status: ready
    when: 'required_phase.id == phase.id'

resolve_with:
  scenario: establish-initial-wayfinding-map@2
  inputs: {}

Read it one line at a time

  1. for_each: '[phase]' creates one Obligation Instance for the exact active Phase.
  2. satisfied_when asks a named query whether a current wayfinding map exists.
  3. If none exists, the instance is unsatisfied. MDLM reports it as a Loose End.
  4. The status rule marks it ready when its subject is the active Phase.
  5. resolve_with names the Resolver Scenario. This Scenario needs no existing datum as input.

The Obligation does not contain instructions for writing a map. It declares the required evidence and points to the contract that can produce it.

Now inspect the work contract

The live establish-initial-wayfinding-map@2 Scenario declares:

  • no inputs;
  • exactly one MAP output;
  • exactly one product-intent QST output;
  • zero or more additional QST outputs;
  • required links, payload values, and completion checks.

MAP and QST are package-defined Lifecycle Data types. Their full meaning can wait. For this trace, they are the exact evidence shape promised by the Scenario.

Two corrections to your explanation

First, a successful submission means the proposal passed the Scenario contract. The uncertainty comes afterward: satisfying one Scenario contract does not mean every current Obligation is satisfied.

Second, MDLM does not pick whichever Scenario "makes most sense." It orders Loose Ends by declared status and identifiers, then selects dispatchable work under fixed attention rules. The same repository and package state produce the same choice.
