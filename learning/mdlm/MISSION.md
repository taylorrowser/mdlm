# Mission: Understand and work confidently with MDLM

## Why
MDLM has grown beyond the user's current mental model. The goal is to regain control of the system so they can operate it, diagnose its decisions, change it safely, and explain how its parts fit together.

## Success looks like
- Operate the full `next → prepare → submit → reevaluate` loop on a real repository.
- Explain an Operator Outcome by tracing Lifecycle Data through package definitions and kernel evaluation.
- Diagnose blocked work, attention requirements, dead ends, invalid states, and stale Assignments.
- Change the Process Package or kernel while preserving their ownership boundary.
- Explain every Scenario supported by the current Example Process Package with a concrete repository state.

## Constraints
- Keep each lesson completable in 10 to 20 minutes.
- Use current repository code, tests, and package definitions as primary sources.
- Keep all course material under `learning/mdlm/` and commit it with the repository.

## Out of scope
- Historical designs except where they explain a current choice.
- Deferred Phase 3 to 6 breadth and claims beyond the implemented bootstrap profile.
